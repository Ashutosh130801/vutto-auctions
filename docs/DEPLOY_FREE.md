# Deploying free

A live URL you can put on a CV, for ₹0, with no credit card.

**The stack:** [Neon](https://neon.com) for Postgres, [Render](https://render.com)
for the API, [Cloudflare Pages](https://pages.cloudflare.com) for the frontend.
About 20 minutes, most of it waiting for builds.




## Step 1 — Postgres on Neon (5 min)

1. Sign up at **[neon.com](https://neon.com)** with GitHub. No card.
2. **Create a project.** Name it `vutto`, pick the region closest to you, and
   accept the default Postgres version.
3. On the dashboard, open **Connect** and copy the connection string. Take the
   **Pooled connection** (it says *Connection pooling* — the host contains
   `-pooler`). It looks like:

   ```
   postgresql://neondb_owner:npg_xxxx@ep-cool-pine-a1-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```

   Keep it somewhere for Step 2.

Neon's free compute suspends
when idle and the pooler absorbs reconnections; the direct endpoint has a much
lower connection ceiling and you will hit it.

The `sslmode` and
`channel_binding` parameters are libpq syntax that asyncpg does not accept —
`app/core/dburl.py` translates them for each driver, so no hand-editing is
needed. (Without that translation the app dies at the first connection with
`connect() got an unexpected keyword argument 'sslmode'`, which is a miserable
thing to debug from a hosted log viewer.)

## Step 2 — API on Render (10 min)

1. Sign up at [render.com](https://render.com) with GitHub. No card for the
   free tier.
2. **New → Blueprint**, select your repo. Render reads
   [`render.yaml`](../render.yaml) and proposes one free web service,
   `vutto-api`. Click **Apply**.
3. It will ask for the two values marked `sync: false`:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | The Neon pooled string from Step 1 |
   | `CORS_ORIGINS` | `http://localhost:5173` for now — you will correct it in Step 4 |

   `SECRET_KEY` is generated by Render; leave it alone. Rotating it later signs
   every session out.
4. Wait for the first build (~5 minutes; Docker builds from scratch).

The container runs `scripts/start.sh`, which applies migrations, seeds the demo
catalogue, then starts uvicorn. Both steps before uvicorn are idempotent, so
redeploys are safe.

**Verify before moving on.** Substitute your service URL:

```bash
API=https://vutto-api-xxxx.onrender.com

curl -s $API/health | jq .
curl -s $API/health/ready | jq .            # database must say "ok"
curl -s "$API/api/v1/auctions?status=LIVE" | jq '.total'   # expect 8
```

If `/health/ready` reports the database as `error`, the connection string is
wrong — check you took the **pooled** endpoint and pasted it whole.

Open `$API/docs` for the interactive API.

## Step 3 — Frontend on Cloudflare Pages (5 min)

Cloudflare Pages rather than Vercel for two reasons: unlimited bandwidth on the
free plan, and Vercel's Hobby tier forbids commercial use.

1. Sign up at **[dash.cloudflare.com](https://dash.cloudflare.com)**.
2. **Workers & Pages → Create → Pages → Connect to Git**, select your repo.
3. Build settings:

   | Field | Value |
   | --- | --- |
   | Framework preset | None |
   | Build command | `npm install && npm run build` |
   | Build output directory | `dist` |
   | Root directory | `frontend` |

4. **Environment variables → Add**, for the *Production* environment:

   | Variable | Value |
   | --- | --- |
   | `VITE_API_BASE_URL` | `https://vutto-api-xxxx.onrender.com` |
   | `NODE_VERSION` | `22` |

   Vite inlines this at build time, so changing it later needs a redeploy, not
   just a restart.

5. **Save and Deploy.** You get `https://<project>.pages.dev`.

`public/_redirects` is already in the repo, so refreshing a deep link like
`/auctions/2022-ktm-duke-390-bs6-3b7c8c` serves the SPA instead of a 404.

---

## Step 4 — Connect the two (2 min)

The API and the frontend are on different origins now, so the browser will
preflight every request. Tell the API to allow it.

Render → `vutto-api` → **Environment** → edit `CORS_ORIGINS`:

```
https://<your-project>.pages.dev
```

No trailing slash. Comma-separate if you want to keep localhost too:

```
https://<your-project>.pages.dev,http://localhost:5173
```

Save; Render restarts automatically (~30 s).

Now open your Pages URL and sign in:

| Role | Email | Password |
| --- | --- | --- |
| Buyer | `aarav@vutto.example.com` | `Demo@12345` |
| Admin | `admin@vutto.example.com` | `Admin@12345` |

**Change the admin password immediately** if the link is public — the seed
credentials are in this repo.
